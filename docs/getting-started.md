# 第一次使用

One Step Closer 是一个以中文为主的穆斯林习惯记录应用。不需要注册或填写 API 密钥，记录保存在当前浏览器中。下面的操作适合先用虚构内容试一遍。

**[打开公开试用版](https://one-step-closer-rho.vercel.app)**，首次使用需要联网。请把这个固定网址加入书签；记录属于当前浏览器和网站地址。会运行项目的用户也可以按 [README](../README.md) 的本地运行步骤使用。

## 打开与记录

1. 从 README 的试用入口打开应用。第一次需要联网。使用同一个浏览器，并把这个网址加入书签，方便之后回来。
2. 在“今日”选择一项饮食记录，试着勾选一次礼拜，或写一句“这是试用记录”。各项都可以自行选择，不必填满。
3. 等待“正在保存”提示消失，再刷新页面。确认刚才的内容仍在；如果出现错误提示，先保留错误文字，不要清除网站数据。
4. 打开“本周”查看本周汇总。“地点”（页面标题为“我的地点”）可手动保存地点；试用时用“示例地点”“虚构街道”。“同行”（Partner Mode）只在这个浏览器中保存一份伙伴记录，不会邀请、通知或同步给别人。

请先用普通浏览窗口试用。隐私浏览可能不保留记录。界面出现内容不代表保存已经完成，关闭页面前请等待保存结束。

## 记录在哪里

应用没有账号，也没有跨设备同步。记录属于当前设备、浏览器资料和网站地址：换一个浏览器、从手机换到电脑、切换域名，或使用不同端口，都会进入另一份存储。网址变了之后看不到原来的记录，不一定意味着原记录已被删除；先回到原网址检查。

应用代码不会上传习惯记录，也没有统计追踪功能；托管平台仍可能保存普通访问日志。本地记录和备份文件都未加密。清除网站数据、卸载或清理浏览器、设备损坏都可能导致记录丢失。需要保留的内容请定期导出到浏览器之外。

## 下载一份备份

1. 打开“设置”，找到“数据备份与恢复”。
2. 点击“导出备份”。根据浏览器提示保存 JSON 文件，或到浏览器的下载列表中查找。
3. 确认文件实际存在，并保存到自己信任的位置。页面显示“已生成备份”不代表你已完成保存。

备份包含全部每日记录、地点、伙伴信息和设置。不要把真实备份放进公开 GitHub issue、聊天群或截图中。文件扩展名应保持为 `.json`，不要手动修改里面的内容。

## 从备份恢复，或换设备使用

先将备份文件通过自己信任的方式带到目标设备，再在目标设备的浏览器打开同一个应用入口。恢复会**替换当前浏览器中的全部四类数据，不会合并，也没有撤销按钮**。如需保留目标浏览器原有内容，先为它单独导出一份备份。

1. 在“设置 → 数据备份与恢复”点击“选择备份文件”，选择本应用导出的 JSON 文件（最大 2 MiB）。文件只在本机浏览器处理，不上传。
2. 检查预览中备份与当前浏览器的记录天数、地点数量和日期范围。此时还没有修改记录；不想继续时点击“取消恢复”。
3. 确认需要替换后，勾选“我了解恢复会替换当前记录”，点击“确认恢复”。
4. 等待“恢复完成”提示，再打开“今日”“地点”或“设置”检查结果。保留原备份文件。

如果提示文件格式或版本不支持，不要修改版本字段来绕过检查。如果提示预览后记录发生变化，先确认哪个窗口更新了记录，再重新选择文件并核对预览。遇到其他错误，记录错误文字并查看[反馈方式](#遇到困难时)。

## 离线、安装与更新

公开试用版需要 HTTPS。首次联网打开生产版本后，应用会缓存五个页面及所需资源；请给浏览器时间完成缓存，再断网尝试刷新和切换页面。缓存是否完成以自己设备上的实际离线检查为准，首次打开后立即断网可能尚未准备好。

浏览器支持时，可以从浏览器菜单选择安装或“添加到主屏幕”。入口和支持情况因设备而异，安装不是使用应用的前提。项目尚未完成 iOS 真机验证；请不要把浏览器自动化测试理解成所有手机都已验证。

发布更新后，先联网打开应用以获取更新，再关闭该网站的所有标签页和已安装应用窗口，重新打开。**不要通过清除网站数据来更新应用，这会删除记录。** 更新前导出备份，完成后检查记录和离线打开是否正常。

如果看到浏览器不支持保存的提示，可以在记录仍能正常读取时导出备份，再到支持的浏览器手动恢复。不要反复切换网址寻找记录，也不要为了消除错误删除存储内容。

## 遇到困难时

使用仓库的 [试用反馈表](https://github.com/musa426/One-Step-Closer/issues/new?template=usability_feedback.md) 说明设备、浏览器、操作步骤和遇到的困难即可。GitHub issue 是公开的，不需要附真实记录、伙伴姓名、地点或备份文件。可以用“示例地点”等虚构内容复现；截图请先检查并遮住个人信息。安全漏洞的报告方式见 [SECURITY.md](../SECURITY.md)。

没有 GitHub 账号也不影响使用应用。参与维护者组织的自愿试用时，可以用已约定的渠道口头或文字反馈；由维护者在得到同意后整理不含身份信息的问题。
